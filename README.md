# Ads Adjust Record

เว็บแอปบันทึกการปรับแต่งแคมเปญ Google Ads — บันทึกเร็ว ดูย้อนหลังได้อิสระ
และคำนวณให้อัตโนมัติว่า "ปรับแล้วดีขึ้นหรือแย่ลง"

หน้าเว็บเป็นไฟล์ static ล้วน (HTML/CSS/JS ไม่มี framework ไม่มี build step)
วางบน GitHub Pages ได้เลย ส่วนข้อมูลเก็บใน Google Sheet ของคุณเอง ผ่าน Apps Script Web App

```
GitHub Pages (หน้าเว็บ)  ──fetch──▶  Apps Script Web App  ──▶  Google Sheet (ข้อมูล)
```

ถ้ายังไม่เชื่อม Google Sheet เว็บก็ใช้งานได้ทันที โดยเก็บข้อมูลไว้ในเบราว์เซอร์เครื่องนั้น
(กันข้อมูลหายด้วยปุ่มดาวน์โหลด JSON/CSV)

| **วางตัวเลขจาก Google Ads** | ปุ่ม 📋 ในกล่องตัวเลข — copy ข้อความจากหน้า Google Ads มาวาง ระบบแยกตัวเลขให้ทุกช่องในคลิกเดียว |

| **หน้า "ตัวเลขรายวัน"** | Cost / Impressions / Clicks / Conversions รายวัน — ดูยอดรวมทุกแคมเปญหรือเจาะรายตัวก็ได้ · กราฟแท่งรายวัน · ตารางแยกรายแคมเปญพร้อม % ของ Cost · ตารางรายวันมีแถวรวมท้ายตาราง · คัดลอกทั้งตารางไปวางในชีตได้ |

| **หน้า งบ & Bid** | ตารางว่าตอนนี้แต่ละแคมเปญตั้งงบ/วัน และ Max CPC ไว้เท่าไหร่ · กด "ตั้งค่า" แก้ได้ในป๊อปอัพ **ค่าเก็บกับตัวแคมเปญ ไม่สร้างบันทึกในไทม์ไลน์** · เตือนแถวที่เกิน 30 วันไม่ได้แตะ และเทียบกับ CPC จริงล่าสุด |

| **ลบบันทึกในไทม์ไลน์** | ปุ่ม 🗑 ลบ ในแต่ละใบ กดแล้วหายทันที ไม่ต้องยืนยัน — มีปุ่ม "เลิกทำ" ให้กดคืนได้ 8 วินาที |
| **แคมเปญที่ใช้บ่อย** | ชิปด้านบนฟอร์ม — แตะเลือกแคมเปญที่จดบ่อยใน 14 วัน แทนการพิมพ์ชื่อยาว ๆ |
| **คีย์ลัด** | `Ctrl+Enter` บันทึก · `Ctrl+Shift+Enter` บันทึกแล้วจดต่อ · `/` ค้นหา · `N` บันทึกใหม่ · `T` สรุปวันนี้ · `1`–`7` สลับแท็บ · `?` ดูคีย์ลัดทั้งหมด |
| **ไทม์ไลน์** | ดูวันนี้ / เมื่อวาน / 7 / 30 / 90 วัน / ทั้งหมด / กำหนดช่วงเอง + กรองซ้อนกันได้ตาม กลุ่ม → สินค้า → แคมเปญ + ค้นหาข้อความ |

| **กราฟเทรนด์** | เส้นเทรนด์รายตัวชี้วัดตามเวลา มีเส้นประบอกวันที่ปรับ กรองตามหมวดหมู่ได้ + การ์ดสรุปตัวชี้วัดหลักทั้งหมด |
| **นำเข้า** | อัปโหลด CSV เดิม หรือวางตารางจาก Google Sheets ระบบอ่านบล็อก Performance เดิม ("Impression = 1,665 / CTR = 22.88% …") ออกมาเป็นตัวเลขให้ |

### จุดที่ระบบคิดให้ต่างจากการจดมือ

1. **คิดเป็น "รอบวัดผล" ไม่ใช่รายครั้ง** — งานจริงคือปรับทุกวันแต่วัดผลเป็นครั้ง ๆ ระบบจึงจับช่วงระหว่างการวัดผลสองครั้งเป็นหนึ่งรอบ:

   ```
   1 ส.ค.  ปรับ + ตัวเลข A     ← เริ่มรอบ
   2 ส.ค.  ปรับ  (ไม่มีตัวเลข)
   3 ส.ค.  ปรับ  (ไม่มีตัวเลข)
   4 ส.ค.  ปรับ  (ไม่มีตัวเลข)
   5 ส.ค.  ปรับ + ตัวเลข B     ← ปิดรอบ → A↔B = ผลรวมของการปรับ 4 ครั้ง
   ```

   บันทึกที่ไม่มีตัวเลขจะไม่ค้างเป็น "รอผล" แต่ได้ผลของรอบที่ตัวเองอยู่
   ระบบไม่อ้างว่าครั้งไหนทำให้ดีขึ้น เพราะแยกไม่ได้จริง — บอกตรง ๆ ว่า "รอบนี้ปรับ 4 ครั้ง ผลรวมคือ…"

2. **แยกไม่ได้รายครั้ง แต่แยกได้รายประเภท** — พอสะสมหลายรอบ การ์ด "ประเภทการปรับไหนเวิร์ก" เทียบให้ว่ารอบที่มี negative keywords ต่างจากรอบที่ปรับ bid อย่างไร พร้อมเตือนเมื่อข้อมูลน้อยกว่า 3 รอบ และบอกว่าปนกับประเภทอื่นกี่แบบ
3. **ปรับเป็นค่าต่อวันก่อนเทียบ** — ถ้าช่วงก่อนปรับยาว 35 วัน แต่ช่วงหลังปรับยาว 10 วัน การเทียบ Conversions ดิบ ๆ จะทำให้ช่วงยาวดูดีเกินจริง ระบบจึงหารด้วยจำนวนวันให้ก่อน แล้วแจ้งเตือนบนหน้าจอว่าทำแบบนี้ (เลือกเป็นค่าดิบได้ในช่อง "วิธีเทียบ")
4. **รู้ว่าตัวชี้วัดไหนยิ่งต่ำยิ่งดี** — CPA/CPC/Lost IS ลดลง = เขียว, CTR/CVR/Conversions/IS เพิ่มขึ้น = เขียว ส่วน Cost และ Max CPC ถือเป็นค่าตั้งค่า ไม่ตัดสินแพ้ชนะ
5. **เดาหมวดหมู่จากชื่อแคมเปญ** — พิมพ์ `21PMax-AirPods` แล้วระบบเติมให้เองว่าสินค้า = AirPods, กลุ่ม = อุปกรณ์เสียง (แก้ทับได้ และจำไว้ให้ครั้งต่อไป)

## หมวดหมู่สินค้า

โครงสร้าง 3 ชั้น + 1 มิติตัดขวาง:

```
กลุ่มสินค้า  →  สินค้า  →  แคมเปญ  →  ad group
```

**ค่าตั้งต้น 7 กลุ่ม / 16 สินค้า** — จัดตามประเภทอุปกรณ์ เพราะ CPA ของสินค้าในกลุ่มเดียวกันอยู่ในระดับใกล้เคียงกัน เทียบกันแล้วมีความหมาย:

| กลุ่ม | สินค้า |
|---|---|
| มือถือ | iPhone, SmartPhone |
| แท็บเล็ต | iPad |
| คอมพิวเตอร์ | MacBook, iMac, Notebook, Computer |
| จอภาพ | Monitor |
| นาฬิกา | Apple Watch, SportWatch |
| อุปกรณ์เสียง | AirPods, Headphone, Speaker |
| เกม | Nintendo, PlayStation, เครื่องเกมอื่น ๆ |

แก้ได้ 2 ทาง — ผลเหมือนกัน เลือกที่ถนัด:

- **ในเว็บแอป:** แท็บ ⚙️ → กล่อง "หมวดหมู่สินค้า" → พิมพ์บรรทัดละกลุ่ม รูปแบบ `กลุ่ม: สินค้า1, สินค้า2` → บันทึก
- **ในชีต:** แก้ชีต `PRODUCTS` โดยตรง (คอลัมน์ `product_group`, `product`)

ระบบเตือนให้ถ้ารูปแบบผิด สินค้าซ้ำสองกลุ่ม หรือกำลังลบสินค้าที่ยังมีบันทึกอ้างอยู่

### หมวดหมู่ผูกไว้ที่แคมเปญ

ตั้งครั้งเดียวต่อแคมเปญในชีต `CAMPAIGNS` (คอลัมน์ `product`) หรือในตาราง "แคมเปญที่บันทึกไว้" ในแท็บตั้งค่า (มีปุ่ม ＋ เพิ่มแคมเปญ ไว้ตั้งล่วงหน้าทีเดียวหลายอัน)
เวลาบันทึกก็แค่เลือกแคมเปญ ที่เหลือเติมให้เอง — บันทึกเก่าที่ยังไม่มีหมวดจะได้หมวดตามแคมเปญทันทีที่ตั้งค่า ไม่ต้องไล่แก้ทีละอัน

### ตั้งชื่อแคมเปญให้ระบบเดาถูก

รูปแบบที่แนะนำ ต่อยอดจากที่ใช้อยู่ (`15Search-Speaker`):

```
<เลขลำดับ><ช่องทาง>-<สินค้า>[-<ขยาย>]

15Search-Speaker
20Shopping-iPhone
21PMax-AirPods            (PMax = Performance Max)
23Search-MacBook-Brand
24Display-Monitor
```

คำที่ระบบรู้จัก: ชื่อสินค้าตรง ๆ และคำพ้องบางคำ เช่น `ลำโพง`→Speaker, `หูฟัง`→Headphone, `switch`→Nintendo, `ps5`→PlayStation, `samsung`→SmartPhone

เดาไม่ออกก็ไม่เป็นไร แค่เลือกจาก dropdown ครั้งเดียว ระบบจำให้

## ติดตั้ง

### ขั้นที่ 1 — สร้าง Google Sheet + Apps Script

1. สร้าง Google Sheet ใหม่ ตั้งชื่อเช่น `Ads Adjust Record DB`
2. เมนู **Extensions → Apps Script**
3. ลบโค้ดเดิมในไฟล์ `Code.gs` ทิ้ง แล้ววางเนื้อหาจาก [`apps-script/Code.gs`](apps-script/Code.gs) ลงไปแทน
4. แก้บรรทัดนี้ให้เป็นรหัสลับของคุณเอง (สุ่มยาว ๆ):
   ```js
   var API_TOKEN = 'CHANGE-ME-เปลี่ยนรหัสนี้ก่อนใช้งาน';
   ```
5. เลือกฟังก์ชัน **`setup`** จาก dropdown ด้านบน แล้วกด **Run** หนึ่งครั้ง
   Google จะขอสิทธิ์เข้าถึง Sheet — กด Review permissions → เลือกบัญชี → Advanced → Go to … (unsafe) → Allow
   เมื่อรันเสร็จ ชีต `RECORDS` และ `CAMPAIGNS` จะถูกสร้างพร้อมหัวตารางให้เอง
6. กด **Deploy → New deployment**
   - Select type: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   - กด Deploy แล้วคัดลอก **Web app URL** (ลงท้ายด้วย `/exec`) เก็บไว้

> ⚠️ ทุกครั้งที่แก้ `Code.gs` ต้องไป **Deploy → Manage deployments → ✏️ → Version: New version → Deploy**
> ไม่งั้น URL เดิมจะยังรันโค้ดเวอร์ชันเก่า

### ขั้นที่ 2 — เอาหน้าเว็บขึ้น Cloudflare Pages

**ทำไมไม่ใช่ GitHub Pages** — GitHub Pages เสิร์ฟไฟล์นิ่ง ๆ อย่างเดียว
เว็บแบบนั้น "เก็บความลับไม่ได้" อะไรที่เบราว์เซอร์ใช้ยิงชีต คนเปิดเว็บก็เปิด DevTools อ่านได้หมด
Cloudflare Pages ให้รันโค้ดฝั่งเซิร์ฟเวอร์ได้ด้วย (โฟลเดอร์ `functions/`)
token จึงอยู่ฝั่งเซิร์ฟเวอร์ ไม่เคยเดินทางมาถึงเบราว์เซอร์เลย

```bash

git init
git add .
git commit -m "Ads Adjust Record"
git branch -M main
git remote add origin https://github.com/<ชื่อผู้ใช้>/ads-adjust-record.git
git push -u origin main
```

จากนั้น:

1. เข้า [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages → Create → Pages → Connect to Git**
2. เลือก repo `ads-adjust-record`
3. Build settings — **ปล่อยว่างทั้งหมด** (เว็บนี้ไม่ต้อง build)
   - Framework preset: **None**
   - Build command: *(เว้นว่าง)*
   - Build output directory: `/`
4. กด **Save and Deploy**
5. เข้า **Settings → Environment variables → Add variable** (ทั้ง Production และ Preview):

   | ชื่อ | ค่า | |
   |---|---|---|
   | `SHEET_URL` | URL ที่ลงท้าย `/exec` จากขั้นที่ 1 | |
   | `API_TOKEN` | รหัสเดียวกับใน `Code.gs` | **กด Encrypt** |

6. กลับไปแท็บ **Deployments → ⋯ → Retry deployment** (ตัวแปรใหม่มีผลกับ deployment ถัดไปเท่านั้น)

เว็บจะขึ้นที่ `https://ads-adjust-record.pages.dev`

> **สำคัญ:** โฟลเดอร์ `functions/` ต้องอยู่ที่ **ราก** ของ repo — Cloudflare ใช้ชื่อโฟลเดอร์เป็นเส้นทาง
> `functions/api/sheet.js` → เว็บเรียกที่ `/api/sheet`
> ในไฟล์ zip ไฟล์นี้อยู่ที่ `cloudflare/functions/api/sheet.js` **ให้ย้าย `functions/` ออกมาไว้ราก repo**
>
> เช็กว่าติดตั้งถูกไหม: เปิด `https://<เว็บของคุณ>/api/sheet` ในเบราว์เซอร์
> ต้องได้ `{"ok":true,"proxy":"ads-adjust-record","configured":true}`
> ถ้า `configured` เป็น `false` = ยังไม่ได้ตั้งตัวแปร หรือยังไม่ได้ retry deployment

### ขั้นที่ 3 — ล็อกไม่ให้คนอื่นเข้า (Cloudflare Access)

ขั้นที่ 2 ซ่อน token ได้แล้ว แต่ **ยังไม่ได้กันคนนอกเข้าเว็บ** — ใครเจอ URL ก็ใช้ได้
ถ้าต้องการกันจริง ๆ (ควรทำ):

1. ใน Cloudflare → **Zero Trust → Access → Applications → Add an application → Self-hosted**
2. Application domain: `ads-adjust-record.pages.dev`
3. Policy → Action: **Allow** → Include: **Emails** → ใส่อีเมลของคุณ
4. Save

หลังจากนี้ เปิดเว็บครั้งแรกจะเจอหน้าให้ใส่อีเมล → Cloudflare ส่งรหัส 6 หลักไปที่เมล → ใส่แล้วเข้าได้
ฟรีถึง 50 คน ไม่ต้องจำรหัสผ่าน

### ขั้นที่ 4 — เปิดใช้งาน

เปิดเว็บได้เลย ไม่ต้องกรอกอะไร ป้ายมุมขวาบนจะขึ้น "Google Sheet" เอง

> ถ้าเปิดจากไฟล์ในเครื่องหรือ GitHub Pages (ไม่มีตัวกลาง) เว็บจะบอกตรง ๆ ว่า
> "ยังไม่พบตัวกลางที่ `/api/sheet`" พร้อมทางเลือกให้กรอก URL + token เองในหน้าตั้งค่า
> ค่าที่กรอกเก็บใน localStorage ของเครื่องนั้นเท่านั้น ไม่ขึ้น repo

## นำข้อมูลเก่าเข้าระบบ

ไปแท็บ **นำเข้า / ตั้งค่า** → กล่อง "นำเข้าข้อมูลเก่า"

- **แนะนำ:** เปิดไฟล์เดิมใน Google Sheets → เลือกทั้งตารางรวมหัวคอลัมน์ → Ctrl+C → วางในช่องข้อความ → กด "วิเคราะห์ข้อมูล"
- หรืออัปโหลดไฟล์ `.csv` โดยตรง (ต้องเป็น **UTF-8** ไม่งั้นภาษาไทยจะเพี้ยน — ใน Google Sheets ใช้ File → Download → Comma-separated values ซึ่งเป็น UTF-8 อยู่แล้ว)

ลำดับคอลัมน์ที่ระบบเข้าใจ:

| 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|
| วันที่ | แคมเปญ | สิ่งที่ปรับ | ประสิทธิภาพก่อนปรับ | เหตุผล | ผลที่คาดหวัง | ประสิทธิภาพหลังปรับ |

ช่อง "ประสิทธิภาพ" จะถูกอ่านด้วย regex รองรับรูปแบบที่จดไว้เดิม:

```
Preformance 3 มิ.ย - 7 ก.ค
Impression = 1,665
CTR = 22.88%
CPC = THB14.60
Conversion = 149.50
Conversion Rate = 39.24%
Cost/Conversion = THB37.21
Impression Share = 77.24%
Maximum CPC Bid Limit = 20THB
Cost ต่อวันเฉลี่ย 43.80 บาท (3 มิ.ย - 7 ก.ค = 5,562.90 THB)
```

รวมถึงช่วงวันที่แบบไทย (`3 มิ.ย - 7 ก.ค`) ซึ่งจะถูกแปลงเป็นวันที่จริงโดยเดาปีจากวันที่ของบันทึกนั้น

หน้าจอจะแสดงตัวอย่างที่อ่านได้ให้ตรวจก่อนเสมอ ค่อยกด "นำเข้าทั้งหมด"

## โครงสร้างชีต `RECORDS`

หัวคอลัมน์ถูกอ่านจาก **ชื่อ** ไม่ใช่ตำแหน่ง — สลับลำดับคอลัมน์ใน Sheet ได้ตามสบาย
และถ้าเวอร์ชันใหม่เพิ่มคอลัมน์ ให้รัน `setup()` ซ้ำ ระบบจะเติมเฉพาะที่ขาด ไม่ลบของเดิม

| กลุ่ม | คอลัมน์ |
|---|---|
| ระบุตัวตน | `id` `created_at` `updated_at` |
| หมวดหมู่ | `product_group` `product` |
| เนื้อหา | `date` `campaign` `ad_group` `tags` `change_detail` `reason` `expected` `result_note` `status` |
| ก่อนปรับ | `before_start` `before_end` `before_impressions` `before_clicks` `before_ctr` `before_cpc` `before_cost` `before_conversions` `before_cvr` `before_cpa` `before_impr_share` `before_lost_rank` `before_lost_budget` `before_max_cpc` |
| หลังปรับ | `after_…` (ชุดเดียวกับข้างบน) |

ชีต `CAMPAIGNS` — `name` `product` `channel` `note` `active` `budget` `bid` `settings_updated`
`budget` / `bid` = ค่าที่ตั้งไว้ตอนนี้ของแคมเปญ (หน้า "งบ & Bid" เขียนลงตรงนี้) — ไม่ใช่บันทึกรายวัน จึงไม่ทำให้ไทม์ไลน์รก
ระบบเพิ่มชื่อใหม่ให้เองเมื่อคุณพิมพ์แคมเปญที่ยังไม่เคยมี และคอลัมน์ `product` มี dropdown ให้เลือกในชีต กันพิมพ์ผิด
(คอลัมน์ `channel` ยังอยู่ในชีตแต่เว็บแอปไม่ใช้แล้ว — จะซ่อนหรือลบทิ้งก็ได้)

ชีต `PRODUCTS` — `product_group` `product` `note` `active` (แหล่งความจริงของหมวดหมู่)

> **v1.3 ย้าย `budget` / `bid` ไปอยู่ที่ชีต `CAMPAIGNS`** — ต้องวาง `Code.gs` ใหม่ทับ แล้ว **Deploy › Manage deployments › ✏️ › New version › Deploy** หนึ่งครั้ง
> ถ้าไม่ทำ ค่างบ/bid ที่ตั้งจะไม่ถูกเขียนลงชีต (ส่วนอื่นของเว็บแอปยังทำงานปกติ)
>
> เวอร์ชันก่อนหน้าเก็บ `budget`/`bid` ไว้ในชีต `RECORDS` และการกด "อัปเดตค่า" จะสร้างบันทึกลงไทม์ไลน์ด้วย
> ตอนนี้ไม่สร้างแล้ว และหน้า "งบ & Bid" จะมีการ์ด **"เก็บกวาดบันทึกที่หน้านี้เคยสร้างไว้"** ขึ้นมาเอง
> ให้ย้ายค่าเก่าไปเก็บกับแคมเปญแล้วลบบันทึกที่ไม่ต้องการทิ้งได้ (บันทึกที่มีตัวเลขวัดผลจะไม่ถูกแตะ)
> คอลัมน์ `budget`/`bid` ใน `RECORDS` ยังอยู่เฉย ๆ ลบทิ้งเองได้ถ้าไม่ต้องการ
>
> **อัปเกรดจากเวอร์ชันก่อน:** วาง `Code.gs` ใหม่ทับ แล้วรัน `setup()` อีกครั้ง — คอลัมน์และชีตที่ขาดจะถูกเติมให้โดยไม่ลบข้อมูลเดิม
> จากนั้นไปตั้งสินค้า/ช่องทางให้แต่ละแคมเปญในตาราง "แคมเปญที่บันทึกไว้" บันทึกเก่าทั้งหมดจะได้หมวดหมู่ทันที

## เรื่องความปลอดภัยที่ควรรู้

Web App ที่ deploy แบบ "Anyone" หมายความว่าใครก็ยิง URL ได้ ระบบจึงกันด้วย `API_TOKEN`

**ป้องกันเป็นชั้น ๆ แบบนี้:**

| ชั้น | กันอะไร | ตั้งที่ไหน |
|---|---|---|
| ตัวกลาง `/api/sheet` | token ไม่หลุดออกมาที่เบราว์เซอร์ | Cloudflare env vars |
| Allowlist คำสั่ง | ยิง action แปลก ๆ ทะลุไปชีตไม่ได้ | `functions/api/sheet.js` |
| Cloudflare Access | คนนอกเปิดเว็บไม่ได้เลย | Zero Trust → Access |
| `API_TOKEN` | คนที่รู้ URL `/exec` ตรง ๆ ยิงไม่ได้ | `Code.gs` |

**สิ่งที่ต้องทำถ้าเคยใช้เวอร์ชันก่อน 1.15:**
เวอร์ชันเก่าฝัง URL + token ไว้ใน `assets/app.js` ถ้า repo เป็น public แปลว่ารหัสนั้น**หลุดไปแล้ว**
(repo private ก็ไม่ช่วย — GitHub Pages ยังเสิร์ฟไฟล์นั้นให้ทุกคนดาวน์โหลดอยู่ดี)
→ เปลี่ยน `API_TOKEN` ใน `Code.gs` เป็นค่าใหม่ → **Deploy → Manage deployments → New version**
→ เอาค่าใหม่ไปใส่ใน Cloudflare env var

**ข้อควรระวังทั่วไป**

- ตั้ง token ให้ยาวและสุ่ม อย่าใช้คำง่าย ๆ
- ตั้งแต่ 1.15 เป็นต้นไป **ในโค้ดไม่มีความลับใด ๆ เลย** เปิด DevTools ดูก็ไม่เจอ
- ถ้าสงสัยว่าหลุด: เปลี่ยน `API_TOKEN` ใน `Code.gs` → Deploy เวอร์ชันใหม่ → แก้ env var ใน Cloudflare → Retry deployment

### การดึงข้อมูลจาก Google Ads อันตรายไหม

ไม่ — สคริปต์ `DailyMetrics.js` รันอยู่ **ในบัญชี Google Ads ของคุณเอง** (Tools → Bulk actions → Scripts)
ไม่มีการให้สิทธิ์กับบุคคลที่สาม ไม่มี API key ของ Ads หลุดออกไปไหน และสคริปต์**อ่านอย่างเดียว**
(`AdsApp.search()` — ไม่มีคำสั่งที่แก้แคมเปญ งบ หรือ bid ได้เลย) เลวร้ายที่สุดคือสคริปต์พัง แล้วตัวเลขไม่อัปเดต
ข้อมูลที่ไหลออกมามีแค่ยอดรวมรายวันที่ส่งเข้าชีตของคุณเอง
